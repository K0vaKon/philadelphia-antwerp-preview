# Сайт церкви «Филадельфия»

Все актуальные файлы сайта находятся в этой папке. Для просмотра откройте
`index.html`; основные страницы сайта — `about.html`, `leaders.html`, `gallery.html`
и `admin.html`.
Для локальной проверки откройте сайт через HTTP-сервер, а не напрямую через `file://`.

CSS-файлы, JavaScript и логотип также лежат рядом с HTML-страницами, поэтому
пути ресурсов не требуют дополнительных папок.

- `backups/` — резервные копии данных сайта.
- `gallery-admin.html` — отдельная страница управления фотографиями.
- `gallery.css` — сетка галереи и миниатюры в админке.
- Последние три видео на странице «О нас» хранятся в `latest-videos.json`; GitHub Actions обновляет их каждые шесть часов.
- События создаются, редактируются и удаляются через защищённое серверное API; список общий для всех посетителей и администраторов.
- Обычная галерея и отдельная галерея праздников используют закрытые серверные хранилища; изображения отдаются посетителям через API, а управление доступно после входа администратора. В админке можно загружать несколько фото за раз; страницу праздников можно включать/выключать и задавать её название на русском, нидерландском и английском языках. При первом входе после миграции старые фото обычной галереи из браузера автоматически переносятся на сервер.
- Лидеры служения, домашние группы, пресвитерские семьи и видимость страниц хранятся на сервере и доступны с любого устройства. При первом входе администратора старая информация из этого браузера переносится на сервер.
- Домашние группы и пресвитеры добавляются и редактируются отдельно в админке, включаются в резервные копии и показываются в таком порядке на странице служений: домашние группы, пресвитеры, лидеры. Для каждой домашней группы указываются лидер, место/район, день недели, описание и фотография. Группы также отображаются горизонтальной прокруткой на главной странице.
- В админке события, домашние группы, пресвитеры, лидеры и резервная копия разделены вкладками; выбранная вкладка сохраняется при перезагрузке страницы.
- Для событий и служений переводы на нидерландский и английский добавляются в админке вручную. Если перевод не заполнен, показывается исходный текст; внешний сервис перевода не используется.
- Дата и время события необязательны. Затемнение фотографии можно включить или отключить при создании и редактировании. Сайт сохраняет соотношение сторон загруженного снимка; для карточек событий рекомендуется вертикальное фото 4:5. Название события тоже необязательно.
- События и записи служений можно редактировать в админке через кнопку «Редактировать» в их строке; новое фото необязательно, без него останется прежнее.
- Выбор языка и активной вкладки админки остаётся локальным предпочтением браузера. Общие записи и настройки сайта в `localStorage` не сохраняются.
- `archive/old-documents-copies/` — старые копии CSS и JavaScript, не используемые сайтом.
- `archive/previous-git-project/` — предыдущая копия проекта с историей Git; не редактируйте её вместо файлов сайта в корне этой папки.

## Размещение на PHP-хостинге

Эта версия требует PHP 8.1 или новее, расширение Sessions и Apache-совместимую обработку `.htaccess`. Для нового размещения рекомендуется PHP 8.4: на сентябрь 2026 года эта ветка ещё получает активные исправления и совместима с требуемым синтаксисом сайта. В панели хостинга выберите PHP 8.4 (либо новее, если версия доступна и поддерживается хостингом) и проверьте версию отдельно для домена `opwekking.org`. PHP 8.1 — только технический минимум, не рекомендуемая версия для нового развёртывания. Для загрузки используйте архив `Philadelphia-Web-server-upload.zip`: он содержит код сайта, но не рабочие данные из `api/storage/`. Распакуйте его в корень сайта (например, `public_html`), сохранив папку `api/` и её вложенную структуру. При ручной загрузке из папки `Philadelphia-Web-server-upload` не заменяйте существующую папку `api/storage/`. Файл с одноразовым кодом настройки храните отдельно и не загружайте на сайт.

Перед настройкой включите HTTPS. Откройте `https://ваш-домен/admin.html`, введите одноразовый код из отдельного файла комплекта и задайте собственный пароль администратора длиной от 12 символов. После успешной настройки одноразовый код перестаёт работать; удалите локальный файл с кодом. Сервер хранит только хеш выбранного пароля в `api/storage/admin-password.json`.

Папка `api/storage/` должна быть доступна PHP для записи (обычно достаточно прав владельца 755 на папку и 644 на файлы). Она закрыта от прямой загрузки через Apache `.htaccess`. Если при публикации сервер сообщает о правах, настройте владельца/права этой папки в панели хостинга; не делайте её общедоступной на запись.

События, записи служений, домашние группы, пресвитерские семьи и настройки страниц хранятся на сервере в `api/storage/events.json` и `api/storage/content.json`. Списки фотографий обычной галереи и галереи праздников находятся в `api/storage/gallery.json` и `api/storage/holiday-gallery.json`; изображения хранятся в закрытых `api/storage/gallery-images/` и `api/storage/holiday-gallery-images/`. Фото выдаются через `api/gallery-image.php`, поэтому прямой доступ к приватным каталогам не требуется. Сделайте резервную копию всей папки `api/storage/` и регулярно скачивайте резервную копию сайта из админки.

В корневом `.htaccess` принудительно включён HTTPS, добавлены HSTS на один год (без `includeSubDomains`), запрет встраивания сайта в чужие фреймы, MIME-sniffing, ограниченная политика Referer, запрет ненужных браузерных API, удаление заголовка версии PHP и запрет просмотра содержимого каталогов. PHP-настройки API отключают отображение ошибок и оставляют журналирование ошибок включённым. Загружайте HTTPS/HSTS-директивы только при включённом HTTPS. Если на сервере уже есть `.htaccess` (например, правила WordPress), сохраните его копию и объедините директивы, а не стирайте существующие правила. `api/.htaccess` дополнительно закрывает прямой доступ к `common.php`, `config.php` и `.user.ini`; папка `api/storage/` защищается отдельным `.htaccess`.

Если в старой версии уже были события, до замены старого сайта скачайте его резервную копию из браузера, где эти события создавали. После первого входа в новую админку импортируйте копию: события будут отправлены на сервер.

При последующих обновлениях сохраните существующую папку `api/storage/` целиком и не загружайте поверх неё файлы из локальной копии сайта. Там хранятся события, фотографии и их метаданные, пароль администратора и сеансы; их замена приведёт к потере данных. Архив обновления исключает рабочие данные из `api/storage/`. Если обновляете сайт вручную, загружайте остальные файлы, не заменяя содержимое `api/storage/`.

При первом входе администратора после установки новая серверная версия переносит лидеров, домашние группы и пресвитерские семьи из `localStorage` именно того браузера, где они были сохранены. Не очищайте данные браузера до этого входа. После успешного переноса локальные копии удаляются. Смена языка и выбранная вкладка админки остаются только настройками интерфейса в браузере; все записи и видимость страниц хранятся на сервере.

`latest-videos.json` включён в комплект. GitHub Actions обновляет этот файл каждые шесть часов; после успешного изменения отдельный workflow запускает публикацию обновлённого сайта на хостинг.

## Автоматическая публикация из GitHub

Workflow `.github/workflows/deploy-to-hosting.yml` публикует сайт на хостинг при каждом push в ветку `main` и по ручному запуску из GitHub Actions. Публикация идёт по явному FTPS (FTP с TLS), а не по незашифрованному FTP. Для неё хостинг должен поддерживать FTPS и предоставлять FTP-аккаунт с доступом к корню сайта.

Перед первым запуском откройте настройки репозитория GitHub: **Settings → Secrets and variables → Actions → New repository secret**. Добавьте:

| Secret | Значение |
| --- | --- |
| `FTP_HOST` | Имя FTP-сервера без `ftp://`, например `ftp.example.com` |
| `FTP_USERNAME` | Имя отдельного FTP-аккаунта |
| `FTP_PASSWORD` | Пароль этого FTP-аккаунта |
| `FTP_REMOTE_DIR` | Папка сайта относительно FTP-корня, обычно `/public_html` |
| `FTP_PORT` | Порт явного FTPS; обычно `21` |

Создайте FTP-аккаунт с доступом только к папке сайта, если панель хостинга это позволяет. Не используйте пароль от панели управления хостингом. После добавления секретов проверьте **Actions → Deploy site to hosting → Run workflow**. Последующие изменения попадут на сайт после push в `main`.

Workflow загружает только файлы, отслеживаемые Git, не удаляет удалённые файлы и намеренно пропускает содержимое `api/storage/`, кроме защитного `.htaccess` и `index.html`. Поэтому опубликованные события, хеш пароля и PHP-сессии не перезаписываются при обновлении. `.gitignore` также исключает серверные данные из Git; добавляйте в репозиторий только файлы `.htaccess` и `index.html` из этой папки. На первом деплое эти файлы создадут защищённую папку хранения, а PHP создаст JSON-файлы при необходимости.

На сервере всё равно нужно выполнить первоначальную настройку: включить HTTPS, открыть `/admin.html`, использовать отдельный одноразовый код настройки и задать пароль для этого сервера. Пароль и события с ноутбука автоматически на хостинг не копируются. Если провайдер предлагает только SFTP или незашифрованный FTP, этот FTPS-workflow к нему не подключится; перед публикацией настройте транспорт под возможности хостинга.

Workflow обновления трёх последних видео после успешного изменения `latest-videos.json` также запускает публикацию на хостинг.
